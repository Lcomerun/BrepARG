## 方案① FSQ:`fsq_quantise.py`

**集成点(已对真实代码验证)**:`trainer.py` 的流水线是 `encoder → quant_conv(128→64) → quantize(2×2→4 token) → post_quant_conv → decoder`。`FSQQuantiser` 是 `quantise.py::VectorQuantiser` 的 **drop-in**,严格匹配返回签名 `(z_q, loss, (perplexity, min_encodings, encoding_indices))`,内部做 64→d 投影、逐位置 FSQ、d→64 反投影,产出与原 VQ 完全一致的 4 个 token(展平顺序 `(b,h,w)`,下游 `reshape(N,4)` 对齐)。

已验证:与真实 `diffusers.VQModel` 端到端集成可前向+反传、index 范围 `[0,4096)`、straight-through 梯度、确定性、占位 embedding 物化正确。

## 方案② RCM + 几何 GNN:`gnn_ordering.py`

**集成点**:替换 `2sequence.py::dfs_face_ordering_from_core`,签名/返回完全一致。这次有一个**重要的设计修正**(下文"坑"里详述):面排序发生在**离线预处理**阶段,GNN 不可能与 AR 端到端联合训练。最终给两级:

- **`rcm_face_ordering`**(零训练):把面排序重述为**带宽最小化**(对应论文附录 A.4 的 MLA),用经典 Reverse Cuthill-McKee 求解。**它本身就已经显著优于论文的 DFS(0.65×)**,可直接一行替换,零风险零依赖。
- **`GNNFaceOrdering` + `train_gnn_ordering`**(可学习):用 RCM 当教师做 pairwise rank 监督,额外喂入面**几何特征**(bbox 质心+尺寸)。价值在于纯拓扑方法对**结构对称的面只能任意 tie-break**,而 GNN 能用几何做**一致的** tie-break——这才是对口你 GNN 背景、且 RCM 给不了的增量。

## 方案③ 约束解码:`constrained_decoding.py`

**集成点**:`generate_brep.py` 用 HuggingFace `model.generate()`,所以用 `LogitsProcessor` 注入,**无需重训**。实现了无状态前缀解析器 + 6 类约束(类型/标记时序/面索引声明/相异/唯一/bbox 单调)。其中 bbox 单调是**①→③ 的协同**:FSQ/标量量化让 token 有几何序,才能施加 `xmax_token ≥ xmin_token`。

已验证最关键的**"必过"测试**:50 个随机 GT 拓扑,逐 token 检查合法序列**任一步都不被错误屏蔽**;同时验证非法 token 确实被屏蔽、不死锁、HF generate 集成不崩。

# 三、需要注意的地方 / 可能失败的地方(最重要)

## 方案①的坑

1. **序列长度 × codebook 的权衡**。FSQ 有效码本 = `prod(levels)`,必须等于下游 `se_codebook_size`,否则词表错位。用 RVQ 会让 geometry token 从 4 变 8,**整条序列翻倍**,长程依赖更重、推理更慢——需同步调 `n_positions`。
2. **`levels` 配置是主要调参点**。`[8,8,8,8]→4096` 对齐原设置最稳;维度 `d` 太小表达力不足、太大 token 爆炸。
3. **重构 loss 降 ≠ Valid 升**。几何更准但拓扑 sew 仍可能失败,**必须直接测 Valid**,别只看重构。
4. **两段都要重训**(VQ-VAE + AR),GPU 预算翻倍。
5. 我用 CPU torch 2.12 测的,真实环境是 torch 2.1.2 + GPU;`autocast`/`amp` 下 FSQ 的 `round_ste` 数值需复测(逻辑无浮点敏感操作,风险低)。

## 方案②的坑(这次踩到的真实问题,必须诚实写进论文)

1. **离线排序 → 端到端不可行**。排序在 `2sequence.py` 预处理阶段、早于 AR 训练,所以 GNN **只能离线预训练后 drop-in**。我最初设想的"用 AR 损失端到端训练排序"**走不通**,除非重构整条流水线让排序在线化(代价极大)。
2. **可微 MLA 损失会塌缩**。我第一版用 `soft_rank` + MLA 损失,实测**只与随机持平**。根因有二,都已在代码注释和 `differentiable_mla_loss` 的 docstring 里诚实标注:
   - 退化解:所有分数相等 → 所有秩≈N/2 → 秩差=0 → 损失≈0 但排序无意义;
   - **随机图几乎不奖励好排序**(实测 degree 降序仅比随机好 2%)。这意味着**测试代理必须用结构化图**(网格/棱柱),否则结论假阳。
3. **纯拓扑 GNN 有对称性天花板**。网格内部面度数全=4、二跳数全相同,**automorphic 节点 GNN 不可分**,无法复刻 RCM 的 traversal tie-break,训练 loss 卡在 margin。**解法是喂几何特征打破对称**——这也正好是 GNN 相对 RCM 的卖点。
4. **审稿人必问:RCM 已经赢 DFS,要 GNN 干嘛?** 必须用"几何感知一致 tie-break + 可微/可端到端潜力"来回答,并在真实数据上展示 GNN > RCM(我只能用合成几何验证趋势,真实数据上的优势需你用 DeepCAD/ABC 的 bbox 实测)。
5. **`face_geom` 对齐**:几何特征必须用**排序前的原始面索引**计算,与 `edge_face_pairs` 对齐,排序后再重排——注释里已写明,弄反会静默破坏。
6. **re-index 仍要保留**:论文的 random re-index 防过拟合逻辑不能删,GNN 学的是相对排序,不受影响。

## 方案③的坑

1. **过强约束降多样性**。这是审稿人必查点:"Valid 涨了是不是牺牲了多样性?" **必须同时报 Novelty/Unique/COV 证明没掉**。
2. **局部约束防不了全局非法**。能防"引用未声明面"这类局部错误,防不了全局非流形/不闭合——这些仍靠后处理。论文里要**诚实界定约束边界**,别夸大。
3. **`prompt_len=1` 假设**。解析器假设单 token prompt(单 START 或单类别 token,即主实验设置)。多 token 示例 prompt 需关约束或改 `prompt_len`。
4. **采样变慢**。每步重解析前缀,需实测是否还在论文的 ~1.5s/B-rep 量级。
5. **未覆盖 OCC 几何库**。`pythonocc`/`occwl` 在测试环境装不上,所以**真实 STEP 重建那一段没测**;约束解码本身(token 层)已充分测,但它对最终 Valid 的真实增益**需你在装了 OCC 的环境跑 `generate_brep.py` 验证**。
